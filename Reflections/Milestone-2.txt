My projects table in Supabase stores each project’s title, summary, live and GitHub links, image URL, tech tags and display order, and the public Projects page reads from it instead of hard-coded data. I enabled Row Level Security with four policies: anyone can read, but insert, update and delete are only allowed when auth.uid() matches my own user ID, and I turned off public sign-ups so no one else can create an account. To prove it, I opened the live site in an incognito window and used the public anon key in the browser console to try every operation as a signed-out visitor. Reading returned all 7 projects, but the insert was rejected with error 42501 (new row violates row-level security policy, status 401), and the update and delete both returned empty results, so nothing changed. My /admin page lets me sign in and add, edit and delete projects, and those changes show up on the public page straight away.
